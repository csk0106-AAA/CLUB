# PRD: 모임 관리 앱 (현재 상태)

> 이 문서는 지금 동작하는 앱을 설명한다. 구조·데이터·권한의 자세한 규칙은 docs/ARCHITECTURE.md 를 본다.
> 처음에는 한 원우회의 송년 워크숍용으로 만들었지만, 지금은 어떤 모임(원우회·동호회·동문회 등)에도 쓸 수 있게 일반화했다.
> 모임 이름, 회원구분, 직책, 소모임은 관리자 화면에서 정한다.

## 1. 목표

- 휴대폰 하나로 모임의 회원 명단, 일정(참석·회비·카풀·숙박·조편성), 게시글, 회비·회칙, 소모임을 관리한다.
- 일정 안에서 서로를 알아가는 활동(내가 누굴까요? / 나의 고민은? / 타임캡슐 등)을 진행하고, 회원 프로필 북을 남긴다.
- 앱 설치·회원가입 없이 링크로 접속한다(PWA로 홈 화면 추가 가능).
- 사용자는 50~60대가 많다. 큰 글자, 큰 버튼, 쉬운 한국어, 한 화면 한 동작을 기본으로 한다.

## 2. 사용자와 역할

| 역할 | 설명 | 들어가는 방법 |
|---|---|---|
| 회원 | 명단에 등록된 회원 | 이름 선택 + 초대코드(연락처 뒷자리 4자리. 연락처가 없으면 공통 초대코드) |
| 관리자 | 권한(모든 권한·회원정보·일정·회비·활동·회의록/회칙·게시글)이 있는 회원 | 회원 로그인 + 관리자 비밀번호(2차) |
| 소모임 직책자 | 소모임에서 직책(대표·총무 등)을 맡은 회원 | 글쓰기 가능. 관리자 비밀번호를 넣으면 소모임관리·활동 템플릿 사용 |
| 진행자 | 일정의 활동을 진행하도록 지정된 회원 | 이름 선택 + 진행자 접속번호 → 진행 화면만 |

- 권한은 직책·소모임 직책별 그룹 권한과 개인 권한을 합쳐 정한다. "모든 권한" 회원은 항상 한 명 이상 있어야 한다.
- 회원구분 "회원대기"는 로그인 목록·알림·참석 대상에서 빠진다.
- 5회 연속 틀리면 1분간 잠긴다. 첫 로그인 때 개인정보 동의를 받는다.

## 3. 화면 구성

하단 탭 4개: 홈 / 일정 / 프로필 북 / 설정. 관리자 화면은 설정 위쪽의 관리자 아이콘으로 들어간다.

### 3.1 홈 (게시글)

- 공개 대상에게 보이는 게시글 목록(고정 글 먼저, 최신순). 공지·고정 표시, NEW / UP 표시, 반응·댓글 수.
- 위쪽: 조직도 아이콘, 종 아이콘(새 글, 소모임 신청 알림, 내 글 댓글).
- 글 양식: 일반 / 설문(주관식·하나·여러 개 고르기) / 투표(복수·익명·마감) / 퀴즈(OX와 해설). 첨부 파일(사진·문서, 파일당 4MB, 10개).
- 반응: 좋아요 · 축하해요 · 감사해요 · 응원해요. 댓글(1000자). 회칙·회비 글은 반응·댓글을 받지 않는다.
- 글쓰기: 게시글 권한 관리자와 소모임 직책자.
- 회비 안내·회칙 글은 관리 화면에서 "올리기"로만 만든다. 올린 순간의 내용이 글에 저장되고(스냅숏), 설정을 바꾸면 다시 올려야 글이 바뀐다.

### 3.2 일정

- 리스트/캘린더 보기. 고정 일정 → 참석 예정·미응답·내 소모임 → 불참·다른 소모임 → 지난 일정 순. NEW / UP 표시.
- 일정 유형: 정기모임 · 워크숍 · 소모임 · 회의 · 미팅(회의·미팅은 회비·카풀·숙박·조편성·활동이 없는 가벼운 일정).
- 일정 화면(한 페이지): D-day, 회비 알림, 일정 카드, 접히는 칸(주요 활동 · 내 참가비 · 안내 · 일정), 회의록(회의 일정), 내 조·카풀·방, 참석 신청(신청 완료 · 참석 안함 · 날짜 바꾸기). 워크숍은 참석 날짜를 고른다.
- 회비: 참석하면 내 회비(참석 날짜·회원구분·직책 조건 반영)와 계좌가 보이고, "입금했어요"로 알린 뒤 관리자가 입금 확인한다.
- 소모임 일정: 모든 회원이 읽을 수 있고, 참석은 그 소모임 회원과 참관자만. 소모임 밖 회원은 "소모임 관리자에게 요청하기"로 참관(이번만) 또는 가입 + 참석을 요청한다 → "관리자 확인 중" → 소모임 직책자가 승인하면 참석 신청까지 된다.
- 활동: 사전 작성·사전 추측 기간에는 일정 화면에서 작성하고, 현장에서는 진행자가 버튼을 누를 때 휴대폰 화면이 켜진다.

### 3.3 프로필 북

- 회원이 공개로 승인한 소개 글(AI 인터뷰로 작성, 별칭 → 실명 공개 시점은 관리자가 정함)과 공개를 고른 성향 글만 보인다.
- 미작성 회원은 이름 없이 인원 수만 알려 준다. NEW / UP 표시.

### 3.4 설정

- 내 정보: 프로필 사진(사진 또는 캐릭터 — 기본 새싹이 + 12띠 동물), 성별, 회사·직책, 연락처, 내 소모임(가입은 신청, 회장이면 소모임 회비 화면).
- 화면: 시스템 / 밝게 / 다크.
- 글자 크기: 1~10단계(보통 5). 글자와 아이콘만 커지고 화면 틀은 그대로다. 이 기기에만 저장.
- 받을 알림(일정 / 게시글 / 프로필 북), 알림 켜기, 소리, 방해 금지 시간, 휴대폰 알림 받기.

## 4. 관리자 화면

| 메뉴 | 하는 일 |
|---|---|
| 모임설정 | 모임 이름(정식·줄임 중 화면 표시), 공통 초대코드, 프로필 실명 공개 시점 |
| 회원관리 | 회원 구분(회원구분·직책·소모임 목록), 회원 명단(붙여넣기 일괄 등록, 추가 열), 조직도, 권한설정(그룹·개인), 회비관리(연회비/월회비·조건별 금액·기간·계좌 → 게시), 회칙(조문·확정 → 게시) |
| 일정관리 | 일정 만들기(초안) → 개요 → "공개 및 회원전달". 탭: 개요 · 회의록(회의) · 신청현황 · 회비 · 활동 · 세부 일정 · 준비 목록 · 비용 · 조편성 · 카풀 · 숙박·방배정. 맨 위 고정, 공개 대상, 단체 대화방 안내 문구 복사(일정 바로가기 링크 포함) |
| 소모임관리 | 소모임별 소개·회원·직책·계좌·소모임 회비, 가입·참관 신청 처리 |
| 활동 템플릿 | 템플릿 목록·버전, 직접/AI로 만들기, AI에게 요청, 개발 요청 |

- 위쪽 줄에 내보내기(JSON/CSV, 모든 권한만, 비공개 내용 제외).
- 관리자 처리할 일(새해 연회비, 대신 처리할 소모임 신청)은 설정의 관리자 아이콘에 숫자로 보인다.

## 5. 활동

### 5.1 활동 템플릿

- 활동의 동작(사전 작성 기간, 현장 단계, 단계마다 회원 화면, 켜지는 때, 진행자 버튼, 참여 대상, 팀/전체, 점수, AI 지침, 진행자 필요 여부)은 템플릿 설정이 정한다.
- 기본 템플릿 3종: 내가 누굴까요? / 나의 고민은? / 타임캡슐.
- 버전: 처음 만든 것이 v1. 저장할 때 "수정(이 버전 고치기)" / "새 버전(vN)" / "새 활동" 중 고른다. 일정에서 고쳐도 같은 방법으로 저장한다.
- AI로 만들기: 대화로 새 템플릿을 만들고 검증을 통과한 것만 저장한다.
- AI에게 요청: 지금 기능으로 되면 설정을 고쳐 주고, 새 기능이 필요하면 개발 요청을 남긴다(상태: 접수 / 진행 중 / 완료 / 보류).

### 5.2 일정에서 활동 진행

- 참여 대상이 "선택한 회원"이면 출석 체크를 완료해야 시작할 수 있다.
- 진행자: 일정 › 활동에서 진행자와 접속번호를 정한다. 진행자가 필요한 활동인데 없으면 관리자가 직접 진행할 수 있고(경고만), 진행자 세션은 막힌다.
- 회원 휴대폰은 2초마다 진행 상태를 읽는다.

### 5.3 기본 활동

- 내가 누굴까요?: 별칭 → AI 인터뷰(필수 질문 + 후속 질문, 음성 입력) → 소개 글·2진실 1거짓 생성 → 수정 요청(지침에 맞지 않으면 거절) → 본인 승인. 신원 정보(이름·회사 등)는 서버가 다시 검사한다. 선택: 명리학 풀이(생년월일 원본은 저장하지 않음). 사전 추측 → 현장(소개 열기, 추측 결과, "저예요", 거짓 투표, 정답, 점수, 동점 룰렛).
- 나의 고민은?: 익명/실명을 골라 미리 작성 → 현장 뽑기, 대화 타이머, 이름 오픈(익명은 "익명", 본인이 직접 밝힐 수 있음).
- 타임캡슐: 팀 구성(관리자 배정·연령대 섞기·랜덤, 확인해야 공개) → 개인 목표·팀 약속 작성 → 봉인. 열림 일시 전에는 서버가 내용을 내려주지 않는다(암호화 저장).

## 6. 알림

- 하단 탭 숫자와 앱 배지: 새 일정·새 글·새 프로필, 소모임 신청, 내 글 댓글.
- 휴대폰 알림(Web Push): 내용 없이 "새 게시물 N개가 있어요"만 보낸다. 공개 대상 + 받을 알림 종류 + 방해 금지 시간을 지킨다.
- 일정은 공개할 때와 공개 후 내용을 바꿀 때 알린다(상태·고정만 바꾸면 알리지 않음).

## 7. 디자인

- C안: 차분한 업무용 평면 스타일. 주색 빨강 #C81616, 보조색 보라 #5B4DE8, 글자 #222222, 회색 바탕. 서체 Noto Sans KR.
- 색은 디자인 토큰으로만 쓰고 다크 모드를 지원한다. 모바일 우선이며 PC에서는 앱 너비를 끌어서 바꿀 수 있다.
- 로딩·빈 상태·오류 안내를 모든 화면에 둔다. 명도 대비 4.5:1 이상.

## 8. 기술 스택과 배포

| 영역 | 선택 |
|---|---|
| 프레임워크 | Next.js 15 (App Router) + TypeScript |
| DB | Neon Postgres (`app_rows` 한 테이블), 없으면 로컬 파일 |
| 인증 | 서명 쿠키(jose) |
| AI | Anthropic Claude API(서버에서만) |
| 알림 | Web Push(VAPID) |
| 호스팅 | Vercel |

환경변수(이름만): DATABASE_URL, SESSION_SECRET, ADMIN_PASSCODE, ANTHROPIC_API_KEY, ANTHROPIC_MODEL(선택), INVITE_CODE(선택), NEXT_PUBLIC_VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, VAPID_SUBJECT.

배포: GitHub 저장소를 Vercel에 Import → 환경변수 등록 → Deploy. 휴대폰은 배포된 https 주소로 접속해야 한다(localhost 링크는 휴대폰에서 열리지 않는다). 자세한 순서는 docs/ARCHITECTURE.md 14장.
