# 모임 관리 앱 개발 설계 (현재 상태)

여러 모임(원우회·동호회 등)에 그대로 쓸 수 있는 회원·일정·게시글 관리 앱이다. 모임 이름, 회원구분, 직책, 소모임은 모두 관리자 화면에서 정한다.
제품 설명은 `PRD.txt`, 이 문서는 구조와 규칙을 적는다. 코드와 다르면 코드가 기준이다.

## 1. 기술 결정

| 항목 | 결정 | 비고 |
|---|---|---|
| 형태 | 반응형 웹 + PWA(홈 화면 추가, `public/sw.js`, `/manifest.webmanifest`) | 네이티브 앱 없음 |
| 프레임워크 | Next.js 15 (App Router) + TypeScript + React 19 | 스타일은 `src/app/globals.css`(토큰) + CSS Modules. Tailwind는 쓰지 않는다 |
| 데이터베이스 | Neon Postgres, 테이블 1개 `app_rows` | `DATABASE_URL`이 없으면 로컬 파일 `.data/db.json` |
| 검증 | zod (모든 API 입력) | |
| 인증 | 서명 쿠키(jose, HS256, 30일) | 회원가입 없음 |
| 실시간 | 폴링 (현장 활동 2초, 진행자 화면 5초, 내 정보 10초, 숫자 배지 60초) | 20명 안팎 규모 |
| AI | Anthropic Claude API, 서버에서만 호출 (`src/lib/ai.ts`) | 키가 없으면 수동 모드 |
| 알림 | Web Push(VAPID, `web-push`) + 앱 배지 | 내용 없는 알림 |
| 호스팅 | Vercel | 리전은 Vercel 프로젝트 설정에서 고른다(서울 `icn1` 권장) |

## 2. 저장소(Store)

- `src/lib/store/index.ts`의 `getStore()`가 `Store` 인터페이스(list/insert/update/remove)를 돌려준다. `DATABASE_URL`이 있으면 `NeonStore`, 없으면 `LocalStore`.
- `NeonStore`는 `app_rows(tab, id, seq bigserial, data jsonb, PRIMARY KEY(tab, id))` 한 테이블에 모든 탭을 저장한다. 첫 호출 때 테이블과 `(tab, seq)` 인덱스를 자동으로 만든다. `seq`가 입력 순서를 지킨다.
- 값은 모두 문자열이고 객체·배열은 JSON 문자열로 저장한다. 열 목록은 `src/lib/store/schema.ts`의 `TABS`가 정하며 목록 밖의 키는 저장하지 않는다.
- 첫 실행 때 기본 설정(모임 이름 "우리 모임", 회원구분 5종), 기본 활동 템플릿 3종, 예시 회원·일정을 넣는다(`seeded*` 플래그).
- 주의: Neon 무료 플랜은 용량·컴퓨트 한도가 있고, 쉬고 있으면 첫 요청이 느리다. 큰 행사 전에 한 번 열어 깨워 둔다.

## 3. 인증과 세션 (`src/lib/auth.ts`, `src/app/api/auth/*`)

| 단계 | 방법 |
|---|---|
| 회원 로그인 | 명단에서 이름 선택 + 초대코드. 초대코드 = 등록된 연락처 뒷자리 4자리. 연락처가 없는 회원만 공통 초대코드(Settings `inviteCode`, 초기값 `INVITE_CODE`) |
| 잠금 | 5회 연속 실패 시 1분(서버 메모리, 인스턴스가 바뀌면 초기화) |
| 관리자 2차 확인 | 권한이 있는 회원이 관리자 화면에 들어갈 때 `ADMIN_PASSCODE` 입력 → 세션 `admin: true` |
| 소모임 직책자 | 관리자 권한이 없어도 소모임관리·활동 템플릿에 들어갈 수 있다. 이때도 관리자 비밀번호를 거쳐야 한다(`adminOrOfficer`) |
| 진행자 접속번호 | 일정 › 활동에서 정한 진행자가 초대코드 대신 접속번호를 넣으면 진행자 세션(`host: [활동 id]`)이 된다. 이 세션은 `/host` 진행 화면만 쓸 수 있고, 진행자가 바뀌면 바로 막힌다 |

- 로그인 화면의 이름 목록(`/api/public/club`)은 이름만 내려주고, 회원구분이 `회원대기`인 회원은 빠진다.
- 첫 로그인 때 개인정보 동의를 받는다.

## 4. 권한 (`src/lib/perms.ts`)

- 권한 목록(`ADMIN_PERMS`): `all`(모든 권한), `members`(회원정보), `events`(일정), `fees`(회비·비용), `activities`(활동·조편성), `minutes`(회의록·회칙), `board`(게시글).
- 최종 권한 `effectivePerms` = 그룹 권한 ∪ 개인 권한.
  - 그룹 권한: Settings `permGroups` = `{ "pos:회장": ["all"], "club:대표": ["board"] … }` — 모임 직책(`pos:`)과 소모임 직책(`club:`)별로 준다.
  - 개인 권한: `Members.perms`. `extra.permsCustom`이 true면 개인 권한만 쓴다.
  - `all`이 있으면 `["all"]`만 남긴다.
- 권한을 바꾸는 변경은 "모든 권한" 관리자만 할 수 있고, 바꾼 뒤에도 "모든 권한" 회원이 한 명 이상 있어야 한다(`checkPermChange`).
- 게시판·회비 화면은 세션이 아니라 지금 DB 기준으로 권한을 다시 계산한다.
- 글쓰기: `all`/`board` 관리자와 소모임 직책자. 회칙 글은 `all`만, 모임 회비 글은 `fees`, 소모임 회비는 관리자(`members`/`fees`) 또는 그 소모임 회장(대표).
- 회원정보(회사·연락처·생년월일)는 관리자 API에서만 내려준다.

## 5. 공개 대상 (`src/lib/audience.ts`)

게시글과 일정이 같은 규칙을 쓴다.

| mode | 고르는 방법 |
|---|---|
| all | 전체 회원 |
| members | 회원을 직접 고름 |
| events | 고른 일정의 참석자를 불러와 고름 |
| clubs | 고른 소모임의 회원을 불러와 고름 |

- 최종 대상은 저장 시점의 `memberIds`다. 작성자에게는 항상 보인다. 알림도 같은 기준으로 보낸다.
- 소모임 일정(`Events.club`): 회원대기가 아닌 모든 회원이 읽을 수 있지만, 참석 신청·회비 알림·활동 참여는 그 소모임 회원과 참관자만 된다(`eventJoinable`).

## 6. 일정

- 유형(`src/lib/event-types.ts`): 정기모임 · 워크숍 · 소모임 · 회의 · 미팅. 회의·미팅은 가벼운 일정이라 회비·카풀·숙박·조편성·활동 탭이 없다. 예전 이름 `전체정기모임`은 읽을 때 `정기모임`으로 고친다.
- 흐름: 만들면 **초안**(회원에게 안 보임) → 관리자가 개요를 채우고 **공개 및 회원전달** → **공개**(상태 `공개`, 알림 발송). 공개 뒤 내용을 고치면 UP 표시와 알림(상태·고정만 바꾸면 알리지 않음). 일정은 지우지 않는다.
- `pinned`: 회원 일정 목록 맨 위에 고정.
- 관리자 일정 화면 탭: 개요 · 회의록(회의 일정만) · 신청현황 · 회비 · 활동 · 세부 일정 · 준비 목록 · 비용 · 조편성 · 카풀 · 숙박·방배정. 개요에서 단체 대화방용 안내 문구를 복사할 수 있고, 맨 끝에 일정 바로가기 링크가 붙는다(로그인 전이면 로그인 뒤 그 일정으로 간다).
- 회비 탭: 기본 회비, 입금 기한, 계좌·예금주, 조건별 회비(참석 날짜·회원구분·직책). 새 일정은 계좌를 모임 회비 계좌(소모임 일정은 소모임 계좌)로 미리 채운다.
- 회원 일정 화면(한 페이지): 위쪽 D-day·회비 알림, 일정 카드, 접히는 칸(주요 활동 · 내 참가비 · 안내 · 일정), 회의 일정이면 회의록, 내 조편성·카풀·방, 아래쪽 참석 신청(신청 완료 · 참석 안함 · 날짜 바꾸기).
- 소모임 일정에 소모임 밖 회원이 참석하려면 "소모임 관리자에게 요청하기" → 참관(이번만) 또는 가입 + 참석 선택 → 처리 전에는 **관리자 확인 중**(취소 가능) → 소모임 직책자(없으면 전체 관리자)가 승인하면 참관자/소모임 회원이 되고 참석 신청까지 들어간다.
- 회의 일정의 회의록: 일시·장소·참석자·안건(상태: 논의 전 / 확정·실행완료 / 새로운 안건 / 보류·삭제 / 후속 조치)·후속 조치. 예전 회의록 게시글은 회의 일정으로 옮긴다.
- 조편성·카풀·방배정·팀 구성은 초안으로 만들고 관리자가 확인(공개)해야 회원에게 보인다.

## 7. 활동 템플릿 (`src/lib/template-schema.ts`, `template-versions.ts`)

활동이 어떻게 반응할지는 코드가 아니라 템플릿 설정이 정한다. 일정에 활동을 넣으면 설정이 복사된다.

| 설정 | 뜻 |
|---|---|
| `preEvent` / `guessPhase` | 일정 며칠 전부터 며칠 전까지 사전 작성·사전 추측. `enabled=false`면 현장에서만 |
| `onsite.steps[]` | 현장 단계: `key`, `label`, `memberScreen`(wait/write/vote/iam_button/pick_person/view), `unlock`(host_click/immediate), `hostButton` |
| `participants` | `all` 전체 회원 / `selected` 출석 체크한 회원만(체크 완료 전에는 시작 불가) |
| `mode` | `all` 전체 활동 / `team` 팀 활동 |
| `scoring` | 점수와 동점 룰렛(소개 활동만) |
| `aiGuides`, `aiCommon`, `interview` | AI 지점별 지침, 공통 지침, 인터뷰 질문·후속 질문 수 |
| `host` | `required`: 진행자가 있어야 진행 가능(없으면 관리자가 직접 진행할 때 경고만, 진행자 세션은 막힘), `note`: 진행자 안내 |

- 기본 템플릿 3종: 내가 누굴까요? / 나의 고민은? / 타임캡슐(모두 `participants: selected`, `host.required: true`). 기본 템플릿은 지울 수 없다.
- 버전: 처음 만든 것이 v1. 저장할 때 고르는 방법이 셋이다 — **수정**(이 버전을 제자리에서 고침, 이 버전을 쓰는 일정 활동에도 반영) / **새 버전**(vN 행 추가, 이미 넣은 활동은 그대로) / **새 활동**(다른 이름의 새 템플릿 v1). 일정에서 고쳐 만든 버전은 출처 일정(`sourceEvent`)을 남긴다. 다른 버전이 있으면 v1을 지울 수 없고, 쓰는 일정 활동이 있는 버전도 지울 수 없다.
- **AI로 만들기**: 대화로 새 템플릿 설정을 만들고 스키마 검증을 통과해야 미리보기·저장된다.
- **AI에게 요청**(편집 중): 지금 기능 조합으로 되면 고친 설정을 돌려주고, 새 코드가 필요하면 **개발 요청** 초안을 만든다. 개발 요청은 관리자 › 활동 템플릿 › 개발 요청(`DevRequests`, 상태: 접수/진행 중/완료/보류, 상태 변경·삭제는 모든 권한)에 쌓인다.
- 진행: 진행자(또는 관리자)가 버튼을 누르면 `LiveState`가 바뀌고, 회원 휴대폰은 2초마다 `/api/events/[id]/live`를 읽어 템플릿 설정대로 화면을 켠다.
- 비밀 보장: 승인 전 소개 초안은 본인만, 타임캡슐 본문은 열림 일시 전에는 API가 내려주지 않는다, 인터뷰 원문·생년월일 원본은 다른 사람에게 보내지 않는다.

## 8. 게시판(홈 탭)

| 양식 | 내용 | 만드는 곳 |
|---|---|---|
| general | 제목·본문 | 글쓰기 |
| survey | 질문 여러 개(주관식·하나 고르기·여러 개 고르기), 마감 | 글쓰기 |
| poll | 보기, 복수 선택, 익명, 마감 | 글쓰기 |
| quiz | O·X 문제와 해설(풀기 전에는 정답을 안 보냄) | 글쓰기 |
| fee | 회비 안내(스냅숏) | 관리자 › 모임설정 › 회비관리, 소모임 회비 |
| rules | 회칙(스냅숏) | 관리자 › 모임설정 › 회칙 |
| minutes | 예전 회의록(읽기·수정만) | 이제 회의 일정 |

- 공지(notice)·맨 위 고정(pinned), 첨부(이미지·PDF·오피스·한글·zip·txt, 파일당 4MB, 글당 10개), 공개 대상.
- 반응(👍 좋아요 · 👏 축하해요 · 🙏 감사해요 · 💪 응원해요)과 댓글. 회칙·회비 글은 받지 않는다. 내 글에 남이 단 댓글은 종 알림.
- NEW / UP: 마지막으로 본 뒤 처음 올라온 글은 NEW, 예전 글이 바뀌면 UP. 일정·프로필 북도 같은 방식.
- 양식 템플릿(글쓰기 기본값)은 관리자가 바꿀 수 있다.

### 8-1. 게시(스냅숏) — 회비관리·회칙 (`src/lib/published.ts`)

- 관리 화면에서 "올리기"를 누르면 그 순간의 회비 설정(연회비/월회비, 조건별 금액, 기간, 계좌, 메모) 또는 확정 회칙 조문을 글의 `data`에 그대로 담는다. 설정을 바꿔도 다시 올리기 전까지 글은 그대로다.
- 새 글로 올리거나 기존 글을 고를 수 있다. 지금 연결된 글은 Settings `publishLinks` = `{ dues, rules, "club:<소모임>" }`.
- 이 글들은 게시판에서 고치지 못하고 관리 화면에서 다시 올린다.
- 소모임 회비: Settings `clubDues[소모임]`. 관리자 또는 그 소모임 회장(대표, 소모임 직책 목록의 첫 번째)이 정하고 올린다. 제목에 `[소모임]`이 붙는다.

## 9. 새 소식 · 알림 (`src/lib/unread.ts`, `src/lib/push.ts`)

- 하단 탭 숫자: 홈(새 글 + 소모임 신청 알림 + 내 글 댓글) · 일정 · 프로필 북. 1분마다 다시 센다. 같은 숫자를 앱 배지에도 쓴다.
- 홈 위쪽 종 아이콘: 새 글, 소모임 가입·참관 신청(처리할 것, 내 신청 결과), 내 글 댓글.
- Web Push: 내용 없이 "새 게시물 N개가 있어요"처럼 숫자와 안내만 보낸다(잠금 화면에 내용 노출 없음). 받는 사람 = 공개 대상 + 알림 켬 + 그 종류(일정/게시글/프로필 북) 켬 + 방해 금지 시간 아님. 소리 끔이면 silent. 만료된 구독은 지운다. VAPID 키가 없으면 보내지 않는다.
- 관리자 처리할 일(설정 화면 관리자 아이콘의 빨간 숫자): 새해 연회비 설정, 직책자 없는 소모임의 신청 대신 처리.

## 11. 화면 구조

- 하단 탭: **홈**(게시글 + 종 알림 + 조직도) · **일정**(목록/캘린더) · **프로필 북** · **설정**.
- 관리자 화면(설정 › 관리자 아이콘, 관리자 비밀번호 필요) 위쪽 메뉴:

| 메뉴 | 하위 화면 |
|---|---|
| 모임설정 | 모임개요(모임 이름(정식/줄임, 화면 표시 선택), 공통 초대코드, 프로필 실명 공개 시점) · 회비관리 · 회칙 |
| 회원관리 | 회원 구분(회원구분·직책·소모임 목록) · 회원 명단 · 조직도(직책 목록 순서대로 나무 그림, 직책마다 회원 여러 명 지정 → 회원 직책 값 변경 / 소모임은 소모임 직책자·모임 주기) · 권한설정 |
| 일정관리 | 일정 목록 → 일정별 탭 |
| 소모임관리 | 소모임 목록 · 신청내역(전체). 소모임 화면 탭: 소모임개요(소개·모임 주기·장소·운영 정책 + 회원·직책) / 회비관리(종류·금액·입금계좌·입금기한·게시) / 소모임일정관리(이 소모임 일정만 만들기·목록, 관리자 › 일정관리에는 안 보임) / 신청내역(승인·반려+사유·처리 내역). 소모임 밖 회원은 소모임 회비 글·소모임 일정에서 '○○ 회원이 아닙니다' + 신청하러 가기 |
| 활동 템플릿 | 활동 템플릿 · 개발 요청 |

- 내보내기(JSON/CSV)는 관리자 위쪽 줄에서, "모든 권한" 관리자만. 인터뷰 원문·타임캡슐 본문·뽑히지 않은 고민·승인 전 초안·명리 풀이·초대코드는 빼고 내보낸다.
- 진행자 화면 `/host`: 진행자 접속번호로 들어오면 진행할 활동만 보인다(프로젝터용 어두운 무대 화면).
- PC(폭 900px 이상)에서는 앱 오른쪽 가장자리를 끌어 앱 너비를 바꿀 수 있다(이 기기에 저장).

## 12. 디자인 시스템 (C안, `src/app/globals.css`)

- 차분한 업무용(flat business) 스타일, 서체 Noto Sans KR. 색은 모두 `:root` 토큰에서만 정한다.

| 토큰 | 밝은 화면 | 쓰임 |
|---|---|---|
| `--red` (주색) | `#C81616` | 주 버튼, 고른 하단 탭, 관리자 탭 밑줄, 알림 숫자, 포커스 |
| `--violet` (보조색) | `#5B4DE8` | 참석·성공·켜짐, 내 소모임, 고른 하위 메뉴, 보기 전환, 링크 |
| `--ink` | `#222222` | 본문 글자 |
| `--page` / `--card` / `--line` | `#F4F5F7` / `#FFFFFF` / `#E6E8EC` | 바탕·카드·테두리 |

- 예전 이름(`--blue*`, `--green*`, `--orange*`)은 새 색에 연결해 두었다(파랑·초록 → 보라, 주황 → 회색 칩).
- 다크 모드: 기기 설정이 다크이고 "밝게"를 고르지 않았을 때, 또는 "다크"를 골랐을 때. `@media (prefers-color-scheme: dark)`와 `:root[data-theme="dark"]` 두 블록 값을 같게 유지한다.
- 글자 크기: `calc(Npx * var(--fs, 1))`. 일정 유형 칩 색: 정기모임 빨강, 워크숍 보라, 소모임 주의(회색), 회의 먹색, 미팅 회색.

## 13. 환경변수

| 이름 | 필수 | 용도 |
|---|---|---|
| `DATABASE_URL` | 배포 시 필수 | Neon Postgres 연결 문자열(없으면 로컬 파일 DB) |
| `SESSION_SECRET` | 필수 | 세션 쿠키 서명(32자 이상 임의 문자열). 프로덕션에서 없으면 오류 |
| `ADMIN_PASSCODE` | 필수 | 관리자 2차 비밀번호 |
| `ANTHROPIC_API_KEY` | AI 기능 | 없으면 AI 기능은 수동 모드 |
| `ANTHROPIC_MODEL` | 선택 | 사용할 모델(기본값은 `src/lib/ai.ts`) |
| `INVITE_CODE` | 선택 | 공통 초대코드 초기값(연락처 없는 회원용, 이후 모임설정에서 변경) |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | 휴대폰 알림 | Web Push 공개키 |
| `VAPID_PRIVATE_KEY` | 휴대폰 알림 | Web Push 비밀키 |
| `VAPID_SUBJECT` | 휴대폰 알림 | `mailto:` 연락처 |

VAPID 키는 `npx web-push generate-vapid-keys`로 만든다. 값은 저장소에 올리지 않는다(`.env.local`, Vercel 환경변수에만).

## 14. 배포 방법 (Vercel)

1. GitHub 저장소를 Vercel에서 **Import** 한다(프레임워크는 Next.js로 자동 인식).
2. Vercel Marketplace에서 Neon Postgres를 연결하거나, 이미 있는 Neon의 연결 문자열을 `DATABASE_URL`로 넣는다.
3. **Settings › Environment Variables**에 13장의 환경변수를 넣는다(Production·Preview).
4. **Deploy**. 첫 요청 때 테이블과 기본 데이터가 자동으로 만들어진다(로컬과 같은 DB를 쓰면 기존 데이터를 그대로 쓴다).
5. 함수 리전을 서울(`icn1`)로 맞추면 빠르다(프로젝트 설정 › Functions).
6. 배포 주소로 접속해 회원 화면·관리자 화면·휴대폰 알림을 한 번씩 확인한다.

- 휴대폰에서는 배포된 주소(https)를 써야 한다. `localhost` 링크는 휴대폰에서 열리지 않고, 일정 바로가기 링크도 지금 연 주소로 만들어지므로 배포 주소에서 복사해야 한다.
- 휴대폰 알림(Web Push)은 https에서만 동작하고, iPhone은 홈 화면에 추가한 앱에서만 받을 수 있다.
